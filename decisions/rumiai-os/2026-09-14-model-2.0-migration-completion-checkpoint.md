# Decisione — Completamento migrazione Model 2.0 e checkpoint pre-freeze

Date: 2026-09-14  
Status: **Accepted — Model 2.0 migration complete; 2.0.0 freeze authorized**

## 1. Scopo

Questa decisione registra il checkpoint completo richiesto da:

```text
specifications/rumiai-os/MODEL-2.0-MIGRATION.md
```

per chiudere formalmente la migrazione architetturale RumiAI OS:

```text
1.0.0 -> 2.0.0
```

Il checkpoint stabilisce che i criteri di completion della sezione 27 della specifica sono soddisfatti per le revisioni e le evidence indicate qui sotto.

Questo documento non retrodata il nome di release `2.0.0` alla revisione prodotto validata: alla revisione di completion il file `product-version` contiene ancora `1.0.0`, come guard intenzionale della fase di migrazione.

L'effetto di questo checkpoint è autorizzare il successivo work unit minimo di freeze che assegna `2.0.0`, riallinea la documentazione/stato di release e converte il guard permanente di test dal divieto pre-completion alla verifica della versione congelata.

## 12. Work unit di freeze autorizzato

Dal commit che contiene questa decisione è autorizzato il work unit finale di freeze, limitato a ciò che serve per trasformare il checkpoint completo nella release identificata come `2.0.0`.

Il delta deve restare minimo e non introdurre nuovi contratti architetturali.

Deve includere almeno il riallineamento coerente di:

```text
rumiai-os/product-version
rumiai-os/README.md stato della migrazione/release
rumiai-tests permanent guard del product-version
rumiai-tests validation target/config applicabile alla revisione finale
```

`pkg-catalog` non richiede un nuovo cambiamento soltanto per il freeze di versione, salvo che emerga un conflitto reale durante il consistency check.

Qualunque modifica semanticamente diversa dal freeze/version alignment riapre il relativo gate e non è coperta automaticamente dalle evidence sopra.

Le proprietà host-dependent già validate non vengono relabellate come evidence di una revisione successiva: la necessità di ulteriori physical validation viene valutata proporzionatamente al delta finale secondo `CONSISTENCY-GATE.md` e `TESTING.md`.
