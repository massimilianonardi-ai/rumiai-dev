# Decisione — Supersession della documentazione attiva per Model 2.0

Date: 2026-09-14  
Status: **Accepted**

## 1. Scopo

Questa decisione chiude le contraddizioni documentali residue emerse durante il release-readiness audit della migrazione RumiAI OS Model 2.0.

Non introduce nuovi contratti di prodotto.

Rende esplicita, nelle fonti correnti, la conseguenza documentale già fissata da:

```text
specifications/rumiai-os/MODEL-2.0-MIGRATION.md
decisions/rumiai-os/2026-09-13-activate-model-2.0-migration.md
```

Il modello 2.0 attivo prevale sulle descrizioni 1.x incompatibili conservate in documenti normativi precedenti.

## 2. Regola di lettura corrente

Per il sottosistema migrato, ogni clausola incompatibile con `MODEL-2.0-MIGRATION.md` è superseded e descrive soltanto la baseline 1.0.x o il modello precedente.

Le clausole non incompatibili dei documenti precedenti restano applicabili.

Non si riscrive la storia e non si relabella l'evidenza storica.

## 3. Documenti con clausole 1.x superseded

Le seguenti fonti contengono ancora testo del modello precedente e devono essere lette secondo questa decisione:

```text
specifications/rumiai-os/BOOTSTRAP-ENVIRONMENT.md
specifications/rumiai-os/COMMAND-ENTRYPOINTS.md
specifications/rumiai-os/ENTRYPOINT-ROOT-RESOLUTION.md
specifications/rumiai-os/FILESYSTEM-NAMING.md
specifications/rumiai-os/POSIX-PORTABILITY-LAYER.md
```

In particolare sono superseded, ovunque compaiano in tali documenti, le assunzioni secondo cui:

```text
rumiai-os è il runtime tecnico/bootstrap root
#!/usr/bin/env rumiai-os è lo shebang integrato corrente
bin/sys/rumiai-os è l'esposizione del runtime tecnico
lib/<runtime>/ è il layout corrente delle librerie
lib/sh/ è il sottalbero shell corrente
m_CONF_DIR, m_DATA_DIR, m_HOME_DIR, m_CACHE_DIR, m_LOG_DIR, m_RUN_DIR, m_TMP_DIR sono root di state correnti
i package state/metadata seguono il layout fisico 1.x superseded
```

## 4. Contratti correnti sostitutivi

I contratti correnti sono quelli già fissati dal modello 2.0:

```text
runtime tecnico root:       $m_ROOT/m
runtime exposure:           bin/sys/m -> ../../m
shebang integrato:          #!/usr/bin/env m
entrypoint branded:         $m_ROOT/rumiai-os
shell branded:              $m_ROOT/rumiai-os-sh
librerie m:                 lib/sys/<runtime>/
librerie RumiAI:            lib/ai/<runtime>/
state semantic root:        $m_ROOT/state
system state selection:     state/system/current -> profile/<profile>
user principal state:       state/user/<host-id>-<uid>
state resolver:             state-path
package runtime ownership:  m
```

Il dettaglio completo resta definito da `MODEL-2.0-MIGRATION.md`; questa decisione non duplica né amplia quella specifica.

## 5. Portability layer

`POSIX-PORTABILITY-LAYER.md` resta corrente per i requisiti di portabilità che non dipendono dall'identità del runtime o dal layout 1.x.

Sono superseded soltanto le formulazioni che identificano `rumiai-os` come bootstrap tecnico, richiedono `#!/usr/bin/env rumiai-os` per i command body integrati o assumono path/layout 1.x.

Le regole POSIX su shell, dati, `eval`, path semantics, side effect, test matrix e static checking restano applicabili dove compatibili col modello 2.0.

## 6. `lang`

`specifications/rumiai-os/LANG-BOOTSTRAP.md` resta corrente.

Nel modello 2.0 il comando pubblico:

```text
bin/sys/lang
```

appartiene al layer tecnico `m` e usa lo standard integrated command entry `#!/usr/bin/env m` secondo `RULES.md` e `MODEL-2.0-MIGRATION.md`.

Il fatto che i cataloghi contengano anche messaggi branded RumiAI non trasferisce il comando `lang` nel namespace `ai`.

## 7. `RULES.md`

`RULES.md` è stato riallineato direttamente al modello 2.0 nello stesso release-readiness work unit.

Non rimangono quindi in `RULES.md` le precedenti regole correnti che imponevano:

```text
#!/usr/bin/env rumiai-os
lib/<runtime>/
rumiai-os come unico runtime/bootstrap root
```

## 8. Nessuna nuova architettura

Questa decisione non introduce:

```text
nuovi entrypoint
nuovi namespace
nuove environment variable
nuove primitive di state
nuovi comandi
nuovi layout package
nuova classificazione stable/development/private
```

Risolve esclusivamente la precedenza documentale già determinata dall'attivazione di Model 2.0.

## 9. Consistency gate

Ai fini del consistency gate della migrazione 2.0:

```text
le clausole 1.x elencate qui sono risolte come superseded
la loro presenza nei documenti storicamente normativi non le rende contratti correnti
le nuove modifiche devono usare soltanto la terminologia e i meccanismi Model 2.0
l'evidenza storica resta immutabile e revision-specific
```

Nuove contraddizioni non coperte da questa decisione restano blocker e devono essere risolte prima del freeze `2.0.0`.

## 10. Invarianti

```text
MODEL2-DOC-01  MODEL-2.0-MIGRATION.md governa i contratti migrati correnti
MODEL2-DOC-02  le clausole 1.x incompatibili elencate sono superseded
MODEL2-DOC-03  le clausole non incompatibili restano applicabili
MODEL2-DOC-04  nessun contratto nuovo viene introdotto da questa decisione
MODEL2-DOC-05  storia ed evidence precedenti non vengono riscritte
MODEL2-DOC-06  nuovi documenti e codice non devono reintrodurre i pattern superseded
```
