# Decisione — Esecuzione della migrazione Model 2.0 su `main`

Date: 2026-09-13  
Status: **Accepted / Active**

## 1. Scopo

Questa decisione fissa il branch operativo usato per continuare la migrazione Model 2.0 già attivata da:

```text
decisions/rumiai-os/2026-09-13-activate-model-2.0-migration.md
```

La migrazione prosegue direttamente sul branch:

```text
rumiai-os/main
```

senza richiedere un branch di migrazione separato.

## 2. Contesto

Il checkpoint pre-migrazione resta storicizzato in modo immutabile dal tag:

```text
1.0.0
```

che punta a:

```text
96d399d0fe0454ed22adf22dc9739af0c8e1ec9a
```

Il lavoro Model 2.0 già presente sul branch temporaneo `model-2.0-migration` forma una storia lineare a partire da quel checkpoint.

Al momento di questa decisione:

```text
rumiai-os/main                 96d399d0fe0454ed22adf22dc9739af0c8e1ec9a
rumiai-os/model-2.0-migration  fb5679ff055595203a38ec4f87d03a84d701a698
```

Il branch di migrazione è 9 commit avanti e 0 commit indietro rispetto a `main`, quindi il passaggio a `main` è un fast-forward puro.

## 3. Effetto sul ruolo di `main`

Durante la migrazione 1.0.0 -> 2.0.0, `rumiai-os/main` è il branch di sviluppo forward-only della migrazione attiva.

Di conseguenza `main` può contenere stati intermedi della migrazione che:

- non rappresentano ancora `2.0.0`;
- non sono ancora il checkpoint completo definito dalla specifica Model 2.0;
- possono avere permanent test o repository dipendenti ancora in attesa di riallineamento secondo l'ordine operativo già fissato.

Questo non modifica né indebolisce il significato del tag `1.0.0`, che resta il checkpoint congelato del modello precedente.

Non viene introdotto un nuovo concetto di release branch o di development branch permanente: questa decisione riguarda soltanto il workflow della migrazione Model 2.0 attualmente attiva.

## 4. Vincoli invariati

Restano invariati:

```text
Git forward-only
nessun force push
nessuna riscrittura della storia
2.0.0 solo al checkpoint completo
ordine operativo rumiai-os -> pkg-catalog -> rumiai-tests
physical evidence revision-specific
nessuna classificazione stable/development/private durante la migrazione
```

Ogni work unit futura su `main` continua a richiedere il normale preflight e il consistency check finale.

## 5. Invarianti

```text
MODEL2-MAIN-01  la migrazione Model 2.0 prosegue direttamente su rumiai-os/main
MODEL2-MAIN-02  il passaggio iniziale dal branch model-2.0-migration a main avviene solo tramite fast-forward
MODEL2-MAIN-03  il tag 1.0.0 resta il checkpoint immutabile del modello precedente
MODEL2-MAIN-04  main può essere temporaneamente incompleto durante la migrazione e non implica 2.0.0
MODEL2-MAIN-05  2.0.0 resta assegnabile solo dopo il checkpoint completo previsto dalla specifica
MODEL2-MAIN-06  il workflow resta Git forward-only e non autorizza force push o history rewrite
```
