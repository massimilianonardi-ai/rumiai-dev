# Decisione — Policy Git-ignore globale per Model 2.0

Date: 2026-09-13  
Status: **Accepted / Active**

## 1. Scopo

Questa decisione fissa la policy Git-ignore durante la migrazione Model 2.0 e supersede, per il modello corrente, la precedente policy per-root definita in:

```text
decisions/rumiai-os/2026-09-08-runtime-state-git-ignore.md
```

La precedente decisione e le relative physical evidence restano storia revision-specific del modello 1.0 e non vengono riscritte.

Questa decisione chiude inoltre il deferment della sola policy Git-ignore contenuto in `specifications/rumiai-os/MODEL-2.0-MIGRATION.md` §24. Le altre parti della sezione restano valide.

## 2. Motivazione

Nel Model 2.0 lo state non e piu organizzato in poche root top-level, ma e annidato per scope, profile, owner, identity e area.

Distribuire `.gitignore` locali nelle directory operative non scala con questo layout e introdurrebbe file di policy dentro un numero crescente di directory runtime.

La policy viene quindi centralizzata esclusivamente nella `.gitignore` della root di `rumiai-os`.

## 3. Nessuna `.gitignore` annidata

`rumiai-os` usa una sola policy Git-ignore versionata:

```text
$m_ROOT/.gitignore
```

Non vengono mantenute `.gitignore` placeholder in:

```text
src/
pkg/
state/
```

o nelle loro sottodirectory.

Le directory operative vengono materializzate quando necessario; Git non deve renderle presenti tramite placeholder.

## 4. Regole globali canoniche

La `.gitignore` root contiene:

```gitignore
.DS_Store
/src/
/pkg/
/state/user/
/state/system/profile/*/*/*/data/
/state/system/profile/*/*/*/home/
/state/system/profile/*/*/*/cache/
/state/system/profile/*/*/*/log/
/state/system/profile/*/*/*/run/
/state/system/profile/*/*/*/tmp/
```

Semantica:

- `.DS_Store` e ignorato a qualsiasi profondita;
- `src/` e il workspace locale e il suo contenuto non appartiene al prodotto;
- `pkg/` e lo store locale materializzato e il suo contenuto operativo non appartiene al repository;
- tutto `state/user/` e state operativo del principal e non appartiene al repository;
- nello state di sistema, le aree `data`, `home`, `cache`, `log`, `run` e `tmp` sono ignorate al livello strutturale esatto `<profile>/<owner>/<identity>/<area>`;
- `conf` di sistema non viene ignorato globalmente, perche configurazione di prodotto versionata puo vivere in state `conf`, come gia avviene per `sys/shell`;
- i pattern sono depth-aware: un owner o identity chiamato `data`, `home`, `cache`, `log`, `run` o `tmp` non viene interpretato accidentalmente come area.

I file gia tracked restano tracked secondo la normale semantica Git.

## 5. Relazione con la struttura Model 2.0

La policy assume esclusivamente le strutture gia fissate:

```text
state/system/profile/<profile>/<owner>/<identity>/<area>/
state/user/<host-id>-<uid>/<owner>/<identity>/<area>/
```

Non introduce nuovi scope, owner, area o convenzioni di pathname.

## 6. Clean cutover: nessuna compatibilita con le vecchie state area

Durante la migrazione Model 2.0, codice ancorato alle vecchie root state top-level non deve essere mantenuto funzionante tramite alias o compatibility layer.

In particolare sono attualmente noti come dipendenti dalle vecchie state area:

```text
bin/sys/pkg-analyze
lib/sys/sh/_pkg-launch.lib.sh
lib/sys/sh/_pkg-state.lib.sh
```

Questi consumer devono essere rimossi o migrati al nuovo modello prima di essere nuovamente considerati operativi. La loro presenza non giustifica la reintroduzione di `m_CONF_DIR`, `m_DATA_DIR`, `m_HOME_DIR`, `m_CACHE_DIR`, `m_LOG_DIR`, `m_RUN_DIR` o `m_TMP_DIR`.

Separatamente, `bin/sys/lang-set` dipende da `m_LANG_DIR`; questa e una dipendenza non-state e non e interessata dalla rimozione delle vecchie state area.

## 7. Test permanente

Il test permanente corrente:

```text
tests/rumiai-os/bootstrap/runtime-state-ignore.test
```

protegge ancora la policy per-root del modello 1.0 e deve essere riallineato alla policy globale dopo l'implementazione in `rumiai-os`.

La precedente physical validation resta valida esclusivamente per le revisioni storiche che ha esercitato e non viene trasferita alla nuova policy.

## 8. Invarianti

```text
GITIGNORE2-01  rumiai-os usa una sola .gitignore versionata alla root
GITIGNORE2-02  non esistono .gitignore placeholder sotto src pkg o state
GITIGNORE2-03  .DS_Store e ignorato a qualsiasi profondita
GITIGNORE2-04  src/ e pkg/ sono ignorati integralmente dalla root
GITIGNORE2-05  state/user/ e ignorato integralmente dalla root
GITIGNORE2-06  nello state system sono ignorate data home cache log run tmp al livello profile/owner/identity/area
GITIGNORE2-07  system conf non e ignorato globalmente
GITIGNORE2-08  i pattern non inferiscono l'area dal nome di owner o identity
GITIGNORE2-09  le directory operative non vengono mantenute nel repository tramite placeholder .gitignore
GITIGNORE2-10  la nuova policy non ripristina compatibilita con le vecchie state area
GITIGNORE2-11  la physical evidence della policy 1.0 resta storica e revision-specific
```
