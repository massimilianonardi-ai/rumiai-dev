## Filesystem naming convention

New normative specification:

```text
specifications/rumiai-os/FILESYSTEM-NAMING.md
```

For filesystem names controlled or automatically generated by RumiAI, the default naming domain is deliberately restricted:

```text
lowercase a-z
0-9
period .
underscore _
hyphen -
```

Controlled names do not contain whitespace or control characters, do not start with `-`, and normally use `-` as the human-readable word separator.

Executable command names remain semantic and do not expose their implementation language.

Explicit user-supplied names and names originating from external tools/data are outside this convention and are treated as opaque pathname data; RumiAI does not silently normalize them merely to make them conform.

## Phase-0 newline simplification

The former sentinel capture mechanism has been removed from phase 0.

Reason:

- the real product entrypoint final component is controlled and fixed as `rumiai-os`;
- RumiAI-controlled names cannot contain newline;
- `command -v` resolves the fixed command name when invocation is through `PATH`;
- `realpath -e` canonicalizes to the controlled final product entrypoint;
- newline characters in externally controlled parent directory components are embedded inside the complete executable pathname, not trailing at its end, so ordinary command substitution preserves them;
- an externally named direct symlink is preserved in `$0` before canonicalization.

The general trailing-newline behavior of POSIX command substitution remains relevant to subsystems that later capture arbitrary external filenames, but it is no longer complexity carried by phase 0.

## Relative PATH correction

Phase 0 no longer requires `command -v` to return an absolute pathname.

A caller's `PATH` may contain relative directory components. The resolved pathname is passed directly to:

```sh
command -p -- realpath -e -- "$RumiAI_BOOTSTRAP_BIN"
```

which performs the physical absolute canonicalization.
