1. CPU con logica discreta

È probabilmente il modo migliore per capire fisicamente come funziona un processore.

Puoi costruirla con circuiti della famiglia 74HC:

  • registri;

  • contatori;

  • ALU;

  • multiplexer;

  • decoder;

  • flip-flop;

  • RAM/EEPROM;

  • clock;

  • bus.

Per esempio:

              +-------------+

3. FPGA

Questa è probabilmente la tecnologia più interessante se l'obiettivo non è solo didattico.

Una FPGA contiene enormi quantità di:

  • LUT;

  • flip-flop;

  • RAM;

  • DSP;

  • interconnessioni programmabili.

Descrivi il processore usando per esempio:

Verilog
SystemVerilog
VHDL

e la FPGA diventa fisicamente quel circuito.

Non stai emulando una CPU come farebbe QEMU. Stai configurando hardware.

Puoi quindi scrivere qualcosa come:

verilog
always @(posedge clk) begin
    case(opcode)
        ADD: r[a] <= r[b] + r[c];
        SUB: r[a] <= r[b] - r[c];
        LOAD: r[a] <= memory[address];
    endcase
end

e sintetizzarlo in un circuito reale.

È possibile creare:

CPU
├── pipeline
├── cache
├── MMU
├── interrupt controller
├── memory controller
├── GPU minimale
├── acceleratori
└── periferiche

tutto nello stesso FPGA.

4. Creare una CPU RISC-V

Qui la cosa diventa particolarmente interessante.

Invece di inventare un instruction set proprietario, puoi implementare RISC-V, che è un ISA aperto.

Per esempio una CPU:

RV32I

ha una base sufficientemente piccola da poter essere implementata personalmente.

Successivamente puoi aggiungere:

M  multiply/divide
A  atomic
F  floating point
D  double precision
C  compressed instructions
V  vector

Quindi puoi costruire:

tuo RTL
   ↓
RISC-V CPU
   ↓
FPGA
   ↓
compiler GCC/LLVM
   ↓
software reale

E arrivare persino a eseguire Linux, se aggiungi le componenti necessarie.

5. CPU microcodificata

C'è una tecnica che trovo particolarmente bella per un progetto domestico.

Separi:

ISA

dalla microarchitettura.

Un'istruzione come:

ADD R1,R2

può diventare una sequenza:

R1 → BUS
R2 → ALU_B
ALU_ADD
ALU_OUT → R1
PC++

Questa sequenza viene memorizzata in una EEPROM.

Hai quindi:

instruction
      ↓
microcode ROM
      ↓
control signals
      ↓
datapath

La cosa interessante è che puoi cambiare l'ISA riprogrammando la ROM, senza rifare l'hardware.

È una specie di “firmware del processore”.

6. CPLD

Tra logica 74xx e FPGA esiste un'altra possibilità:

CPLD

Sono dispositivi programmabili più piccoli e semplici delle FPGA.

Ottimi per:

  • decoder;

  • bus controller;

  • state machine;

  • piccoli processori;

  • glue logic.

Una CPU minimalista può tranquillamente stare in un CPLD.

Questo è già l'equivalente macroscopico di uno dei mattoni fondamentali dei processori fotonici: un interferometro Mach–Zehnder.

La cosa sorprendente è ciò che puoi calcolare semplicemente controllando fase e intensità.

Perché l'interferenza può diventare calcolo

Supponiamo di dividere un raggio in due:

             ┌── percorso A ── φ1 ──┐
luce ────────┤                      ├──► output
             └── percorso B ── φ2 ──┘

Quando li ricombini:

φ1 = φ2
→ interferenza costruttiva
→ molta luce

φ1 = φ2 + π
→ interferenza distruttiva
→ quasi niente luce

Possiamo interpretare:

luce        = 1
buio        = 0

oppure, molto più utilmente:

ampiezza = numero
fase     = numero

È proprio la seconda interpretazione che rende la fotonica potentissima.

Non costruirei una CPU ottica. Costruirei una ALU analogica fotonica

Qui cambia completamente il paradigma.

Una CPU convenzionale fa:

ADD
MUL

STORE
JMP

Un circuito fotonico è invece naturalmente molto bravo a fare:

y=Mx

cioè moltiplicazioni matrice-vettore.

Una rete di interferometri può essere:

x1 ──┬──── MZI ─── MZI ─────► y1
     │       ╲       ╲
x2 ──┼──── MZI ─── MZI ─────► y2
     │       ╲       ╲
x3 ──┼──── MZI ─── MZI ─────► y3
     │       ╲       ╲
x4 ──┴──── MZI ─── MZI ─────► y4

Le fasi degli interferometri rappresentano i pesi della matrice.

Questo approccio è una delle tecniche fondamentali usate negli acceleratori fotonici per AI; esistono anche architetture che sfruttano wavelength-division multiplexing e trasformazioni ottiche nello spazio libero. Nature

MUL
ADD
...

la propagazione stessa della luce è il calcolo.

E la fibra ha anche una proprietà incredibile: è memoria

La luce impiega circa 5 ns a percorrere un metro di fibra.

Quindi:

1 m       ≈       5 ns
100 m     ≈     500 ns
1 km      ≈       5 µs

Avvolgendo della fibra:

       ┌────────────────────┐
       │                    │
       │      1 km fiber    │
       │                    │
       └─────────┬──────────┘
                 │
           delayed signal

hai una delay line.

E quindi puoi fare:

output(t)
     │
     └── fibra ──────► output(t-τ)
            │
            └────────► feedback

Questo non è un espediente sperimentale: le delay-line in fibra sono state realmente utilizzate come elementi computazionali.

L'F2 Ultra UV non è il tipo di laser normalmente usato per “scrivere fibre dentro il vetro”.

Le guide ottiche 3D nel vetro vengono normalmente prodotte mediante femtosecond laser direct writing: impulsi ultracorti focalizzati producono una modifica controllata dell'indice di rifrazione all'interno del vetro.
