1. Cosa consente Apple

Le condizioni della licenza macOS prevedono:

  • Hardware Apple: macOS deve essere eseguito su hardware Apple.

  • Virtualizzazione: la licenza standard consente fino a due istanze macOS virtualizzate aggiuntive su un Mac che esegue già macOS.

  • Sviluppo e test: sono espressamente contemplati tra gli utilizzi consentiti.

  • Headless: la licenza non impone di utilizzare una GUI per interagire con le VM.

  • Hardware non Apple: installare macOS su un normale server x86 con Proxmox non è autorizzato dalla licenza standard.

Il limite delle due istanze e le finalità consentite risultano dalla sezione 2B(iii) della licenza Apple; la versione macOS 27 mantiene questa impostazione, salvo eventuali autorizzazioni specifiche concesse da Apple. Apple+1

4. E se volessimo sviluppare esclusivamente da Linux?

Esistono anche alternative interessanti.

Darling: compatibilità macOS su Linux

Darling — sito ufficiale

Darling è concettualmente simile a Wine, ma rivolto a macOS.

Il suo scopo è eseguire software macOS direttamente su Linux, senza avviare una macchina virtuale.

Implementa varie componenti di Darwin, tra cui Mach, librerie di sistema e persino parti dell'ambiente launchd.

È particolarmente interessante per effettuare esperimenti di compatibilità.

Tuttavia, non lo considererei un sostituto dei test su macOS reale: implementare il comportamento di launchd non significa riprodurre integralmente quello del sistema operativo Apple, incluse autorizzazioni, servizi e integrazioni.

GitHub

Compilazione incrociata

Per il software nativo esiste anche osxcross, che permette di compilare programmi destinati a macOS utilizzando Linux.

Bisogna però procurarsi un SDK macOS e rispettarne la licenza.

Inoltre, la compilazione incrociata non permette di verificare il comportamento di componenti come launchd, Keychain o i servizi di sistema. GitHub

Per shell script, JavaScript e buona parte del software multipiattaforma, invece, possiamo già sviluppare quasi tutto su Linux senza alcuno strumento speciale.

Per tutto ciò che riguarda i servizi di sistema e la shell, la prospettiva è particolarmente buona.

Una limitazione architetturale importante

Su Apple Silicon, macOS virtualizzato è ARM64.

Non puoi creare una VM macOS Intel x86_64 utilizzando Virtualization.framework su un Mac ARM.

Analogamente, non puoi utilizzare questo framework per avviare macOS su Linux: è un componente del sistema operativo macOS.

Questo significa che, per testare contemporaneamente macOS Intel e macOS ARM, serve una strategia diversa, che comprenda anche hardware Mac Intel per i test nativi x86_64.

2. Apple Virtualization.framework: costruire direttamente il proprio gestore di VM

Questa soluzione consiste nello sviluppare un programma macOS che utilizza direttamente le API Apple.

È tecnicamente interessante perché consente di definire un ambiente di virtualizzazione specifico per le proprie esigenze.

Come funzionerebbe

Il programma potrebbe essere una piccola applicazione a riga di comando, scritta in Swift.

Per esempio, dal punto di vista concettuale:

macvm create
macvm install
macvm start
macvm stop
macvm status
macvm delete

macvm è soltanto un nome illustrativo, non un comando esistente che sto proponendo di introdurre.

L'applicazione gestirebbe:

  1. La configurazione delle risorse.

  2. Il download delle immagini macOS.

  3. La creazione del disco virtuale.

  4. L'installazione del sistema operativo.

  5. L'avvio e l'arresto della VM.

  6. L'esposizione della connettività di rete.

  7. L'eventuale salvataggio e ripristino dello stato.

Installazione di macOS

Apple distribuisce le immagini di ripristino macOS anche in formato IPSW.

Virtualization.framework permette di utilizzare queste immagini per installare macOS nelle macchine virtuali.

L'API VZMacOSRestoreImage consente di ottenere l'immagine della versione più recente compatibile con l'host oppure caricarne una già disponibile localmente.

Non significa però che ogni versione di macOS possa essere eseguita su qualunque Mac: la compatibilità deve essere verificata rispetto all'hardware e al sistema host. Apple Developer

Le VM possono essere headless?

Sì.

VZVirtualMachineView serve a visualizzare e controllare graficamente una VM, ma non è indispensabile esporre una finestra per l'esecuzione del sistema guest.

Un'applicazione potrebbe quindi:

  • Avviare una VM senza mostrare finestre.

  • Lasciare il sistema operativo guest in esecuzione.

  • Comunicare con il guest mediante SSH.

  • Raccogliere risultati e log.

  • Spegnere la VM al termine dei test.

C'è però una distinzione: l'assenza di una finestra non garantisce, da sola, che l'applicazione possa essere avviata correttamente in qualsiasi contesto headless, specialmente prima del login dell'utente host.

Questo va verificato separatamente.

Salvataggio e ripristino

Apple supporta il salvataggio e il ripristino dello stato di esecuzione delle VM tramite:

Swift

restoreMachineStateFrom(...)

Queste API permettono di sospendere l'esecuzione e successivamente riprenderla, purché la configurazione sia compatibile.

Sono disponibili per le configurazioni supportate a partire da macOS 14. Apple Developer

Non vanno confuse con snapshot completi e persistenti del disco: il salvataggio dello stato della CPU e della memoria non equivale a creare un checkpoint autonomo di tutto il filesystem.

Per ottenere ambienti ripristinabili occorre quindi gestire coerentemente anche le immagini disco.

3. UTM: la virtualizzazione macOS orientata alla gestione interattiva

UTM — sito ufficiale

UTM è un'applicazione gratuita e open source, con interfaccia grafica, per eseguire sistemi operativi virtualizzati o emulati.

La caratteristica più interessante è che supporta due backend distinti.

BackendTecnologiaUtilizzo
Apple VirtualizationVirtualization.frameworkmacOS ARM64 e sistemi guest compatibili
QEMUQEMU, eventualmente con accelerazione hardwareLinux, Windows, architetture differenti e sistemi storici

Per eseguire macOS su Apple Silicon, UTM utilizza il backend Apple Virtualization, non QEMU. È il backend necessario per questo tipo di guest. GitHub+1

Installazione e gestione delle VM

UTM offre un'interfaccia molto simile a quella di VMware Fusion.

Puoi creare una VM, assegnare memoria e processori, selezionare un'immagine di installazione e avviare macOS in una finestra.

Il programma può scaricare automaticamente l'IPSW macOS più recente compatibile con il sistema host.

I guest macOS sono supportati su Apple Silicon a partire da macOS 12. UTM Documentation

Può funzionare headless?

Sì, ma bisogna distinguere due cose.

Una VM senza finestra non è necessariamente una VM gestita da un servizio di sistema indipendente dalla sessione utente.

UTM supporta la modalità headless: la macchina virtuale funziona in background senza una finestra di visualizzazione.

La documentazione specifica però che l'applicazione UTM deve rimanere aperta mentre la VM è in esecuzione. docs.getutm.app

Per un Mac mini dedicato ai test, questo è gestibile. Tuttavia, un'installazione pensata per funzionare come server autonomo deve considerare la sessione utente che esegue UTM.

Gestione tramite CLI

UTM comprende un comando chiamato utmctl:

Bash
/Applications/UTM.app/Contents/MacOS/utmctl

Permette, tra le altre operazioni, di elencare, avviare, arrestare e sospendere le macchine virtuali.

Per esempio:

Bash

utmctl start "macOS Test"
utmctl stop "macOS Test"

Puoi utilizzarlo anche attraverso SSH:

Bash
ssh mac-mini 'utmctl list'
ssh mac-mini 'utmctl start "macOS Test"'

Quest'ultimo esempio presuppone che utmctl sia nel PATH e che UTM sia accessibile nella sessione macOS che esegue il comando.

UTM offre anche un'interfaccia AppleScript, più ampia della CLI, e l'integrazione con Shortcuts. docs.getutm.app

Questo rende possibile automatizzare molte operazioni senza sviluppare direttamente contro Virtualization.framework.

Una limitazione da conoscere

UTM comprende anche una funzionalità chiamata UTM Server per il controllo remoto.

Attualmente questa funzionalità supporta soltanto le VM QEMU, non quelle macOS eseguite mediante il backend Apple.

Non la considererei quindi una soluzione di gestione remota delle VM macOS. UTM Documentation

Gli snapshot permettono di salvare lo stato dei dischi e ripristinarlo in seguito, con la VM arrestata o sospesa.

UTM supporta inoltre una modalità disposable, che consente di avviare la VM senza conservare le modifiche effettuate sui dischi.

Queste funzionalità erano precedentemente disponibili soprattutto per il backend QEMU.

4. Tart: la virtualizzazione macOS pensata per automazione e CI

Sito ufficiale di Tart · Repository GitHub

Tart parte da una filosofia differente rispetto a UTM.

Anziché concentrarsi sulla gestione interattiva delle macchine virtuali, considera le VM ambienti di esecuzione riproducibili, creabili e distruggibili mediante comandi.

Questo lo rende particolarmente interessante per un'infrastruttura di test automatizzati.

Tart è scritto in Swift, utilizza Virtualization.framework e supporta guest macOS e Linux su Apple Silicon. GitHub

4.1 Gestione tramite CLI

Tart dispone di un'interfaccia a riga di comando.

Per installarlo su un Mac Apple Silicon:

Bash

Per ottenere una VM macOS già predisposta:

Bash

  ghcr.io/cirruslabs/macos-tahoe-base:latest \

Bash

Per avviarla senza interfaccia grafica:

Bash

Il comando resta normalmente in esecuzione mentre la VM è attiva. Per un utilizzo remoto permanente occorre quindi gestire il processo Tart con una sessione persistente o un opportuno meccanismo di supervisione.

Bash
tart ip macos-test-01

Bash

I comandi sono supportati dal progetto e dalla sua documentazione. github.com+1
