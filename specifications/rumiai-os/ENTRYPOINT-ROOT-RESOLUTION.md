# RumiAI OS — Entrypoint and Root Resolution

Status: **Normative specification**  
Date: 2026-08-28

## 1. Scope

This specification defines **phase 0** of the `rumiai-os` bootstrap: the minimum code that must execute before RumiAI can locate and initialize its own infrastructure.

Phase 0 resolves and validates the two fundamental exported variables:

```text
RumiAI_BOOTSTRAP_BIN
RumiAI_ROOT
```

Normative baseline:

**POSIX.1-2024 / The Open Group Base Specifications Issue 8**.

Normative keywords **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** express requirement strength.

---

## 2. Fundamental state

Capitalization of the two exported variable names is normative.

### ENTRY-ROOT-001 — `RumiAI_BOOTSTRAP_BIN`

After successful phase 0, `RumiAI_BOOTSTRAP_BIN` MUST be the absolute physical/canonical pathname of the actual `rumiai-os` executable file.

It MUST:

- be absolute;
- contain no unresolved symbolic-link component;
- contain no effective `.` or `..` component;
- refer to an existing regular file;
- identify the final target when invocation occurred through symbolic links.

### ENTRY-ROOT-002 — `RumiAI_ROOT`

After successful phase 0, `RumiAI_ROOT` MUST be the absolute physical/canonical pathname of the directory containing `RumiAI_BOOTSTRAP_BIN`.

It MUST:

- be absolute;
- contain no unresolved symbolic-link component;
- exist;
- be accessible in the bootstrap execution context;
- satisfy a successful:

```sh
cd -- "$RumiAI_ROOT"
```

### ENTRY-ROOT-003 — exported and immutable in the bootstrap shell

After all invariants succeed, both variables MUST be exported and SHOULD be marked readonly in the bootstrap shell:

```sh
export -- RumiAI_BOOTSTRAP_BIN RumiAI_ROOT
readonly -- RumiAI_BOOTSTRAP_BIN RumiAI_ROOT
```

They MUST NOT be exported before validation succeeds.

## 3. Phase-0 output contract

### ENTRY-ROOT-004 — no user-facing messages

Phase 0 MUST NOT emit localized or explanatory user-facing messages.

It executes before the RumiAI logger and i18n subsystem are available.

### ENTRY-ROOT-005 — suppress utility diagnostics

Diagnostics generated by utilities invoked during phase 0 SHOULD be suppressed when phase 0 is able to control them.

For example, failure from `realpath` or `cd` must not leak host-specific or host-localized explanatory text when the bootstrap can replace it with its own stable failure identifier.

### ENTRY-ROOT-006 — symbolic fatal identifier plus numeric exit status

A phase-0 failure that occurs after the bootstrap script has started MUST, where possible:

1. write exactly one stable symbolic fatal identifier to standard error;
2. terminate with the corresponding numeric exit status.

Initial mapping:

```text
RumiAI_BOOTSTRAP_FATAL_PATH_RESOLUTION_ERROR = 10
RumiAI_BOOTSTRAP_FATAL_REALPATH_ERROR        = 11
RumiAI_BOOTSTRAP_FATAL_BIN_ERROR             = 12
RumiAI_BOOTSTRAP_FATAL_ROOT_ERROR            = 13
```

Example:

```sh
printf -- '%s\n' 'RumiAI_BOOTSTRAP_FATAL_REALPATH_ERROR' >&2
exit "$RumiAI_BOOTSTRAP_FATAL_REALPATH_ERROR"
```

The symbolic identifier is intentionally language-neutral and stable. It is not a localized user message.

Exit statuses 10–13 are reserved by the current phase-0 contract for these failures.

### ENTRY-ROOT-007 — failures before script execution

Failures that prevent the shell from starting `rumiai-os` at all are outside phase 0's control.

Examples include failure to execute the interpreter from the shebang or a symbolic-link loop that prevents the operating system/shell from opening the entrypoint before any script code runs.

Such failures MAY produce host diagnostics and host-selected exit statuses because RumiAI code has not yet begun execution.

## 4. Invocation resolution

The bootstrap MUST support at least:

```text
./rumiai-os
relative/path/rumiai-os
/absolute/path/rumiai-os
rumiai-os resolved through PATH
absolute symbolic link
relative symbolic link
symbolic-link chain
symbolic link in an intermediate pathname component
```

### ENTRY-ROOT-008 — pathname invocation

When `$0` contains `/`, phase 0 MUST use it as the invocation pathname and MUST NOT perform a redundant `PATH` lookup.

### ENTRY-ROOT-009 — `PATH` invocation

When `$0` contains no `/`, phase 0 MUST resolve it through the current `PATH` with:

```sh
command -v -- "$0"
```

The current `PATH` is required here because the purpose is to reconstruct the command location selected for the actual invocation.

The result MUST be an absolute pathname for the supported external-entrypoint case. Failure or a non-path result MUST terminate with `RumiAI_BOOTSTRAP_FATAL_PATH_RESOLUTION_ERROR`.

---

## 5. Physical canonicalization

### ENTRY-ROOT-010 — use standard `realpath`

Phase 0 MUST delegate physical pathname canonicalization to the POSIX Issue 8 `realpath` utility rather than implement a custom symbolic-link resolver.

The standard utility SHOULD be selected through the POSIX default utility path:

```sh
command -p -- realpath -e -- "$RumiAI_BOOTSTRAP_BIN"
```

Using `command -p` here intentionally differs from `command -v` used for entrypoint lookup:

- entrypoint lookup must reproduce the caller's current `PATH` selection;
- the `realpath` dependency should use the standard utility environment rather than an arbitrary earlier command in the caller's `PATH`.

### ENTRY-ROOT-011 — `realpath -e` is mandatory for this contract

POSIX.1-2024 Issue 8 defines both `-e` and `-E` and states that portable applications should explicitly select one because behavior without either option differs across implementations.

RumiAI MUST use:

```sh
realpath -e -- pathname
```

because phase 0 requires every pathname component, including the final bootstrap file, to exist.

The previous design choice to omit `-e` is superseded.

### ENTRY-ROOT-012 — no historical/custom resolver

Phase 0 MUST NOT use:

```text
ls -l parsing
manual recursive symbolic-link traversal
GNU readlink -f
GNU-specific realpath options
```

### ENTRY-ROOT-013 — final regular-file check

After canonicalization, the resolved bootstrap executable MUST satisfy:

```sh
[ -f "$RumiAI_BOOTSTRAP_BIN" ]
```

Failure MUST terminate with `RumiAI_BOOTSTRAP_FATAL_BIN_ERROR`.

## 6. Root derivation and validation

### ENTRY-ROOT-014 — parameter expansion

After `RumiAI_BOOTSTRAP_BIN` is canonicalized and verified as an absolute regular-file pathname, its parent directory MUST be derived with:

```sh
RumiAI_ROOT=${RumiAI_BOOTSTRAP_BIN%/*}
[ -n "$RumiAI_ROOT" ] || RumiAI_ROOT=/
```

### ENTRY-ROOT-015 — `dirname` is intentionally not used here

`dirname` remains a valid POSIX utility, but it MUST NOT be used in the accepted phase-0 path merely to derive the parent of the already constrained canonical bootstrap pathname.

For this domain, parameter expansion is simpler and avoids another process/output-capture boundary.

If the basename is needed in the same constrained domain, prefer:

```sh
${RumiAI_BOOTSTRAP_BIN##*/}
```

### ENTRY-ROOT-016 — mandatory root accessibility check

Before export, phase 0 MUST verify:

```sh
(cd -- "$RumiAI_ROOT")
```

The subshell prevents mutation of the main process current working directory.

Utility diagnostics SHOULD be suppressed. Failure MUST terminate with `RumiAI_BOOTSTRAP_FATAL_ROOT_ERROR`.

## 7. CLI delimiter policy

### ENTRY-ROOT-017 — mandatory `--` where supported

Every phase-0 utility invocation MUST obey the canonical RumiAI delimiter rule:

- if the specific utility supports `--` as option terminator and receives one or more operand/data arguments, `--` MUST be used;
- with zero operand/data arguments, `--` MUST NOT be added;
- `--` MUST NOT be invented for utilities whose contract does not support that semantic.

This applies to POSIX and non-POSIX tools alike.

For the current phase-0 implementation, relevant supported forms include:

```sh
command -v -- "$0"
command -p -- realpath -e -- "$RumiAI_BOOTSTRAP_BIN"
printf -- '%s\n' identifier
cd -- "$RumiAI_ROOT"
export -- RumiAI_BOOTSTRAP_BIN RumiAI_ROOT
readonly -- RumiAI_BOOTSTRAP_BIN RumiAI_ROOT
unset -f -- function_name
unset -v -- variable_name
```

`test` / `[` does not receive an invented `--` delimiter.

---

## 8. Pathname output capture

### ENTRY-ROOT-018 — trailing newline preservation

Ordinary shell command substitution removes trailing newline bytes.

Phase 0 MUST NOT silently corrupt a valid pathname merely because its final component contains newline bytes when the host utility can represent that pathname.

The accepted implementation therefore uses a minimal sentinel protocol around line-producing pathname utilities and removes:

1. the sentinel added by the bootstrap;
2. exactly one utility line terminator.

The mechanism remains local to phase 0 unless a broader serialization requirement later justifies a reusable facility.

---

## 9. Internal phase-0 state

### ENTRY-ROOT-019 — minimal internal namespace

Phase-0 helper variables and helper functions SHOULD use the `RumiAI_` application namespace and MUST NOT be exported unless they are part of the public bootstrap contract.

### ENTRY-ROOT-020 — cleanup before phase 1

After successful export and readonly protection of the two fundamental variables, phase-0-only helper state SHOULD be removed before phase 1 begins.

The stable state crossing the boundary is therefore primarily:

```text
RumiAI_BOOTSTRAP_BIN
RumiAI_ROOT
```

---

## 10. Phase boundary

A successful phase 0 ends when:

```text
RumiAI_BOOTSTRAP_BIN is valid
RumiAI_ROOT is valid
both are exported
both are readonly in the bootstrap shell
phase-0 helper state is cleaned up
```

Immediately after that boundary, phase 1 begins.

The first phase-1 responsibility is to initialize the minimal internationalization infrastructure and the RumiAI logger. After the logger becomes active, normal RumiAI diagnostics MUST be routed through it rather than printed directly by bootstrap code.

## 11. Required validation matrix

Validation MUST include at least:

```text
success produces no stdout/stderr
relative invocation
absolute invocation
PATH invocation
relative symbolic link
absolute symbolic link
symbolic-link chain
symbolic link in an intermediate component
pathname with spaces
pathname containing literal " -> "
leading-dash pathname component
arbitrary caller CWD
successful cd -- "$RumiAI_ROOT"
RumiAI_BOOTSTRAP_BIN is absolute/canonical/regular
RumiAI_ROOT is absolute/canonical/accessibile
exported variables are present in child processes
bootstrap variables are readonly in the bootstrap shell
controlled realpath failure -> identifier + status 11
controlled invalid-bin failure -> identifier + status 12
controlled root failure -> identifier + status 13
```

A `PATH` resolution failure MUST be separately exercised when a harness can create that state after script execution has begun.

Symbolic-link loops that prevent the script from being opened at all MUST be classified as **pre-phase-0 loader failures**, not falsely reported as evidence that RumiAI's own phase-0 error path ran.

Newline-containing pathname cases SHOULD remain robustness tests on hosts/filesystems that permit them.

The same contract SHOULD be run on multiple independent `/bin/sh` implementations and on each reference host before host certification.
